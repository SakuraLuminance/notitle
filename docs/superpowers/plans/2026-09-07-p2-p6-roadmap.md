## P2 — 效果器栏 Phase-Plant 化（**全部完成**：Run #112 第一批 8 类型 + Run #114 第二批（全 14 类型参数表 + 枚举 tooltip + IMPORT 按钮 + strictness 3 绿），HEAD 5023849；剩余可选 = rack 内 MIDI Learn + 枚举参数升级为真菜单控件）

**问题**：EffectRackComponent 其实已是 Phase Plant 式骨架（`EffectSlotWidget`：加/删/上下移/bypass/mix/lo/hi/mod + `+ Add Effect` 菜单 + UndoableAction），但**每个效果器模块自己的参数完全没有 UI**——每槽只有 3-4 个通用滑条，Rate/Size/Tone/Depth 等"真正的"参数无从下手，所以"不知所云"。

**目标形态**：点击槽位展开"参数编辑行"（Phase Plant 式），按效果类型渲染专属 knob 集；折叠恢复 32px 紧凑行。

**侦察清单（开工前必查）**：
- `src/gui/EffectRackComponent.cpp`：EffectSlotWidget 现在怎么把 mix/lo/hi/mod 写回 EffectsChain（数据通道与节流方式）；`getAvailableEffectTypes()` / `createEffectByName()` 的类型名清单；`rebuildSlots()` 触发时机。
- `src/dsp/EffectsChain.{h,cpp}`：slot 数据结构（EffectBase 接口：有哪些通用参数访问器？getState/setState？）；`PresetFactory`/`ProcessorStore` 里模块类型注册表。
- 目标模块各自的参数面：优先 8 个常用（Drive、Chorus、Delay、Reverb、Distortion、EQ、Compressor、Limiter）→ 第二批（Phaser/Flanger/RingMod/Bitcrusher/Saturation/StereoWidener/DeEsser/Dynamics…）。每个模块列出：参数 id/中文名/范围/默认值/读取与写入 API；**没有访问器的模块需要补**（保持向后兼容：PresetManager round-trip 测试必须仍绿）。

**设计骨架**：
- `EffectParamPanel`（新组件）：接收 `EffectBase&` + 模块类型 id，内部按注册表渲染 knob/滑条行；注册表 = `std::map<juce::String, std::vector<ParamSpec>>`（ParamSpec：id、label、min、max、default、skew、getter、setter——用 std::function 绑定到具体模块实例）。
- EffectSlotWidget 增加展开按钮（▾/▸），展开时在自身下方插入 60-90px 的 EffectParamPanel（在 rack 的 contentPanel 里 reserve 高度；viewport 自动滚）。
- 节流：拖 knob → 立即调 setter（参考现有 mixSlider 的通道；若现有通道有 timer 聚合则沿用，避免每 sample 更新）。
- MIDI Learn：新参数顺手注册（沿用 `setupMidiLearnForSlider` 模式需要编辑器指计——rack 在 editor 内部，可给 rack 传一个注册回调）。
- **护栏**：541 用例 + pluginval strictness 2；effect preset round-trip 系列测试是回归红线。

**验收**：加任意常用效果 → 展开能看专属参数名（不缩写黑话）→ 拖动即时生效 → 折叠/展开/重排不崩；preset 保存/加载带这些参数。

**规模估计**：2 轮 CI（第一批 8 模块 + 框架；第二批余量模块）。

## P3 — 信息架构重组（Serum/Harmor 式分页）

**问题**：1100×780 里 7 个区域同屏（Timbre A/中央/ effects/mod/底部六合一/状态栏），详略失衡；LOAD（导入采样）是右下角小按钮。

**目标形态**（建议稿，需用户确认后写 spec）：
- 标题栏：`[IMPORT SAMPLE]`（大按钮，原 LOAD 语义）+ PRESET + LIVE 频谱常驻中央。
- 主区改 **tab 分页**（左侧竖排或顶部横排，Serum 式）：`TIMBRE | FILTER | MOD | SEQ | FX | MASTER`：
  - TIMBRE：Timbre A/B + blend（P5 接线后全部生效）
  - FILTER：FilterPanel（现有）
  - MOD：ModulationAssignPanel + P4 的包络编辑器 + LFO
  - SEQ：SequencerPanel（现有）
  - FX：EffectRackComponent（现有，P2 增强）
  - MASTER：MasterSection + metering + Unison/Voice/Arp（这三个要不要独立 PLAY 页，问用户）
- 中央频谱（LIVE/PARTIALS…视图组）**脱离 tab、常驻**（Serum 的顶部 oscilloscope 模式）。
- 底部状态栏保留（status/dna/credits/randomize/metering）。

**侦察清单**：tab 容器实现选型（juce::TabbedComponent vs 手写按钮组——主题一致性）；各 panel 的最小尺寸约束（TimbrePanel 17% 宽的像素级布局假设在 tab 页内如何重排——Phase 3 的 panels 布局是按"占据原区域"写的，进 tab 后要按新区域重写 resized 的百分比，**但控件几何只需面板内部协调，无跨面板耦合**）；modViewport/modPanel 的 setSize(300, calcContentHeight) 约定。

**验收**：所有现有控件在分页后仍可达且不丢状态；541+ 测试与 pluginval 绿；用户主观"不臃肿"。

**规模估计**：1-2 轮 CI。

## P4（原始问题陈述，保留备查）

**问题**：DSP 有完整 `MultiPointEnvelope`（断点/曲线/loop 模式，tests 已覆盖）与 `LFOSystem`、`ModulationBus`、`runEnvPool`，但 UI 只有 ModulationAssignPanel 顶部 4 个 ADSR 滑条；没有画布。

**目标形态**：
- `EnvelopeCanvas`：断点拖拽（值/时间）、每段曲线形状（MultiPointEnvelope 的段曲线契约：曲线属**段末**断点，见 HANDOFF §1 契约）、loop 区间（Forward/PingPong，注意"loop 点未配置 = play once"语义）、release 行为。
- ENV 槽位：先接 Volume ADSR（现有 4 滑条迁入画布）+ ENV1/ENV2（runEnvPool 已有池语义）。
- 指派：复用 ModulationAssignPanel 的 section/rows 数据（目标参数下拉 + depth），ENV 作为 source 加入 source combo。
- LFO：波形可视化 + rate/depth（LFOSystem 自定义波形编辑列为可选项——侦察后定）。

**侦察清单**：MultiPointEnvelope 公开 API（setPoints/setCurve/setLoop/isActive/process）；runEnvPool 在 processor 侧的暴露方式；ModulationAssignPanel 的 row→slotIndex 映射与 ModulationMatrix 关系；LFOSystem 波形种类与自定义程度。

**验收**：画 ENV1 → 指派 filter cutoff → 播放可闻扫频；headless paint + envelope 单元测试。

**规模估计**：2 轮 CI（画布+Volume；ENV1/2+指派）。

## P5 — 前沿功能接线 —— ✓ 已完成（Round 1-3；spec `docs/superpowers/specs/2026-09-17-p5-frontier-wiring-design.md`）

**完成形态**（Round 1 Run #35212902795 / Round 2 Run #35214745836 / Round 3 Run #35216572487，HEAD 98b1238，583 用例 + strictness 5）：
- **Round 1 — GENERATIVE TIMBRE**：`GenerativeTimbreDesigner` 接线到 partial 域（`applyTimbreProcessing()` 尾部按 mix 混合），TIMBRE 页新增 `GEN` 开关 / `RND` / `CAP` / 8 预设下拉 / mix 滑条；enable+mix 已持久化；`test_generative_timbre.cpp` 增补 `applyToPartials` mix 语义用例。
- **Round 2 — PARTICLES 视图**：新增 `ana::ParticleDisplay`；`viewModeCombo_` 增 "PARTICLES"（id 7）；粒子物理由 editor timer（消息线程）驱动，**不入音频线程**；headless paint 测试。
- **Round 3 — SPECTRAL FREEZE**：FX 页 `FREEZE` 开关 / `TRIG` / 模式下拉（Snapshot/Accumulate/Motion/Reverse）/ mix 滑条；接入音频路径的**两条输出路径**（采样播放 + SYNTH/fallback），位置在 effects/multiFilter 之后、master volume 之前；enable/mode/mix 已持久化。
  - **顺手修 DSP bug**：`SpectralFreezeEngine::processAudio` 原本读的还是"持续移动的环形缓冲"（等于延迟线，冻结的音会随输入漂走，与类文档"SNAPSHOT holds it indefinitely"矛盾）。改为触发时把最近 ring 内容快照到 `capturedAudio_` 并**循环播放该快照**（Reverse 倒放 / Motion 按 evolutionRate 慢速 / Accumulate 缓慢融入输入），`process()`（partial 路径）未动。新增"冻结后喂静音仍有声、解冻后回到静音"用例。
- **HPSS：有意不接** —— `HPSSEngine` 是离线分析（每次调用分配大量临时 vector + 新建 FFT），无实时价值且零测试；按"不接线就不出现在 UI"原则不暴露。
- 侦察后确认**已接线、无需处理**：`SpectralDNA/SpectralDNAEvolver`（EvolutionPanel callout）、`DualTimbre`（P6 A/B blend）。

**原始目标形态（保留备查，已完成项标注）**：

3. DualTimbre A/B ✓（P6 完成）
4. SpectralFreeze ✓ / GenerativeTimbreDesigner ✓ / HPSS ✗（不接）/ QuantumSpectral — 保持零引用（评估后无 UI 收益）

**验收**：每个接线功能可从 UI 触发 + 有单元测试 + pluginval 绿 ✓；未接线的 HPSS/QuantumSpectral 不出现在 UI ✓。

## 建议执行顺序与依赖

```
P2(效果器参数) ──┐
P3(信息架构) ────┼─→ 依赖关系：P3 改变面板归宿，P4/P5 的新面板应直接放进 P3 后的布局；
P4(包络) ────────┤   因此推荐：P2 → P3 → P4 → P5 → P6
P5(前沿接线) ────┘   （P5 的 DualTimbre 是 P6 blend 的前置）
P6(采样减法) ─────   （P6 的 blend 依赖 P5-3）
```

用户可随时改顺序（P2 与 P3 互换的代价：P4/P5 面板要适配方一次）。
